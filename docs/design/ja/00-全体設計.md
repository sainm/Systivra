## 2. 調査で判明し、設計を変えた 6 つの事実

「実施前に必ず公式情報を確認する」とされていた項目を 2026-11-05 に調査した。その結果、当初前提の一部を修正する必要があった。

| # | 事実（確認済み） | 設計への影響 |
|---|---|---|
| F-01 | GitHub Copilot SDK は 2026-06-02 に GA。Node / Python / Go / .NET / **Rust** / Java の 6 SDK。BYOK は OpenAI 互換エンドポイント（独自 `baseUrl` 含む）に対応 | ただし実行時は **Copilot CLI のサイドカープロセス**（JSON-RPC）。GitHub アカウントを持たない閉域網では前提にできない。**AI Provider は二実装**とする（`OpenAiCompatProvider` を既定、`CopilotRuntimeProvider` を任意） |
| F-02 | Neo4j は 2025 年以降**カレンダーバージョン**（2026.10.1 が最新）。**2026.x は LTS ではない**：各月版は翌月版リリースまでしか hotfix されない。唯一の LTS は 5.26（2024-12-06 リリース、2028-06-06 まで hotfix）。Community 版は GPLv3 | Neo4j は**バイナリに組み込まず、リンクもしない**。独立サービスとして配置。バージョンは 5.26 に固定（ADR-013）。「PostgreSQL を正本、Neo4j を再構築可能な投影」とする判断を補強 |
| F-03 | 旧 Java 意味解析基盤は、外部 classpath と独立 JVM 実行を前提とする | **未採用（ADR-017）**。Tree-sitter とプロジェクト内シンボル索引を最終方式とする |
| F-04 | Tree-sitter は 0.25.10。公式 grammar に **XML は存在しない**（HTML / JSON / Java / JS / TS / CSS / SQL など） | XML / Dicon / web.xml は `quick-xml` で解析。JSP は grammar がないため、**HTML 解析 + scriptlet 再解析**のハイブリッドを自作。工数見積の最大の落とし穴 |
| F-05 | pgvector は 0.8.6（2026-07-29）。0.8.3 で HNSW vacuum 時の**インデックス破損**を修正 | 本番 HNSW の最低バージョンは **0.8.4**、目標 0.8.6。0.8 の iterative index scan を必須で有効化（フィルタ後の recall 崩壊を防ぐ） |
| F-06 | Docling 2.142.1（MIT）、Playwright 1.65.0（Apache-2.0、Node ≥ 20）、PostgreSQL 18.6 | Excel 設計書は Docling を使わない。`calamine` + OOXML 直接解析で、結合セル・図形アンカー・数式/キャッシュ値を保持。Phase 1 の PDF は `pdf-extract` |

> 調査方法：公式サイト、GitHub Release、crates.io API、npm registry、Maven Central。調査日 2026-11-05。フロントエンド依存のバージョンは本調査の対象外とし、Phase 0 末に lockfile で固定する。

## 3. 前提条件

| ID | 前提 | 崩れた場合の影響 |
|---|---|---|
| A-01 | 最初の対象は Java 17 中心の Java Web。Java 8 構文と Struts1 系レガシーを含む | Java アナライザーに旧構文のフォールバックが必要 |
| A-02 | 単一プロジェクト規模：**設計書 60,000 本（大半が Excel）、Java 13,000 ファイル、JSP 1,000+**、embedding chunk 1,200 万（上限 2,000 万）、行単位の証拠 1.44 億（保存しない）、Fact 250 万（上限 500 万）、グラフ entity 84 万（chunk を含めない） | 単一 PG の索引と HNSW が破綻する。32〜64 パーティション、分割索引、解析成果物のオブジェクトストレージ退避が必須 |
| A-03 | 既定は顧客閉域網。外部ネットワーク前提なし。AI Provider は完全停止可能 | 外部接続が必要な場合、監査とマスキングを追加 |
| A-04 | 単一インスタンスの利用者 200 名未満。マルチテナントは論理分離（行 + schema） | 物理分離と独立鍵管理が必要 |
| A-05 | **設計書は日本語**。UI も日本語を既定、中国語・英語は副次 | 用語集・フォント・検索・組版を再設計 |
| A-06 | テスト実行環境は顧客提供。プラットフォームは環境を供給しない | 環境管理モジュールが必要 |
| A-07 | **ソースコードの自動修正は行わない**。差分提案まで。確定は人間が行う | 書き込み権限・ロールバック・コードホスティング連携が必要 |
| A-08 | バージョン基準は Git のリビジョン。SVN は未導入（将来拡張）。なければ snapshot（tree digest） | 増分分析と再現性が劣化 |
| A-09 | Graph は派生データであり再構築可能であることを顧客が許容 | Neo4j を正本とする設計に変更が必要 |
| A-10 | 初期はプロジェクト間の知識共用を行わない | 共通オントロジーとエンティティ整合が必要 |

> A-02 は 2026-11-05 の実規模ヒアリングで改訂した（設計書 60,000 本・大半 Excel、Java 13,000、JSP 1,000+）。算出根拠・容量・受入値は `reference/scale-model.md`、速度の内訳は `detail/03-performance.md` に置く。以下の容量と性能目標はこの規模を前提とする。
>
> **A-02 の「単一プロジェクト」が分区設計を決める**：`project_id` をパーティションキーにすると全 1,200 万行が 1 区に集中するため、`corpus.chunk` は `HASH(id)`、`corpus.embedding_1024` は `HASH(chunk_id)` で 32〜64 分割する。`project_id` は列 + 索引 + RLS で強制し、検索は全分区へ並列 fan-out する（`05-データモデル.md` §1.4、`detail/03-performance.md` §2）。

## 4. 日本語文書を扱ううえでの 6 つの留意点

「文書が日本語である」ことは、UI の翻訳問題ではない。解析・保存・検索・コード解析・テストデータ・帳票の 6 層に影響する。英語前提で実装すると、実案件で必ず手戻りする。

| # | 課題 | 設計上の対応 | 反映先 |
|---|---|---|---|
| J-01 | **文字コード**：レガシー案件では Shift_JIS / Windows-31J が普通。JSP、Java、SQL、CSV が混在 | 取り込み時に `chardetng` で推定 + `encoding_rs` で変換。**元バイト列・元エンコーディング・変換後テキスト**を保持。コードのエビデンス位置は**元バイトオフセット**基準 | 04.4 / 05 |
| J-02 | **分かち書きがない**：`to_tsvector` がそのままでは機能しない | Lindera(IPADIC) で事前分割。索引とクエリで同一の tokenizer / 辞書バージョンを使用し、索引メタデータに記録 | 04.1 / ADR-007 |
| J-03 | **正規化**：旧字体（髙・﨑）、全半角、半角カナ、送り仮名 | **二系統**：照合は NFKC + 旧字体マップ、保存とエビデンスは原文（NFC）。`quote` の照合は原文（NFC）で行い、正規化後の文字列を証拠にしない | 04.1 / 05 |
| J-04 | **PDF 組版**：縦書き、ルビ、スキャン | Docling のレイアウト解析 + 日本語 OCR。縦書きは `writing_mode: vertical` を locator に記録。ルビは独立テキスト層として保持し、本文に混ぜない | 04.1 |
| J-05 | **組版規則**：禁則処理、和暦、全角括弧 | PDF 帳票は日本語フォント埋め込み + 禁則処理。Phase 1 の UI 日付は西暦（和暦は Phase 2。保存は ISO 8601） | 07 |
| J-06 | **テストデータ**：全角数字、全角空白、外字、サロゲートペア、結合文字、和暦 | 日本語境界値セットを生成器に内蔵。`length` は「文字数 / バイト数 / コードポイント数」を区別 | 04.6 |

> J-01 が最も危険である。文字コードを誤っても「ファイルは開ける」ため、即座にエラーにならない。気づいたときには行番号・証拠・差分がすべてずれている。

## 5. 意思決定（2026-11-05 / 11-06 確定）

| ID | 論点 | 結論 | 理由 | 状態 |
|---|---|---|---|---|
| D-01 | Neo4j バージョン | **5.26.32 LTS**。2028-06-06 まで hotfix。2026.x は互換検証のみ | **「2026.x LTS」は存在しない**。カレンダー版は毎月更新が前提で、閉域網の製品には不適 | 確定 |
| D-02 | 日本語全文検索 | **階層型**：L1 Lindera + tsvector 常時、L2 pg_bigm があれば有効、L3 PGroonga は既存環境の再利用のみ。クエリルーティング + RRF | 「単語単位」と「文字単位」は別パラダイム。どちらか一方では必ず半分の検索が成立しない | 確定 |
| D-03 | Graph の正本 | **PostgreSQL を SoR、Neo4j を再構築可能な投影**（ADR-002） | Provider 差し替えの前提は「Neo4j を捨ててもデータが残る」こと | 確定 |
| D-04 | Workflow エンジン | **自作**（Rust ステートマシン + YAML）。`WorkflowRuntime` port は残す | 初期はノード数が少なく、Capability / 承認との結合が深い。Temporal は運用面が大きすぎる | 確定 |
| D-05 | グラフ描画 | **Cytoscape.js は関係図、React Flow はフロー図**。混用しない | データモデルと操作体系が異なる | 確定 |
| D-06 | デモ資産 | **SAMPLE プロジェクトを自作**（24 画面、`is_sample=true`、UI 透かし、帳票マーク） | 顧客資料の入手待ちで Phase 4 が止まるのを避ける。サンプルは必ず識別可能にする | 確定 |
| D-07 | フロント依存 | Phase 0 末に `package-lock.json` で固定。本書にバージョン番号を書かない | 2 週間で古くなる | 確定 |
| D-08 | テナント / KB 範囲 | **単一プロジェクト専用。project 自体を知識ベースとし、日本語要件・版管理・K1〜K4 の段階分割を含む**（ADR-015） | 対象は特定の日本語 JavaWeb プロジェクト 1 件。マルチテナント・KB 管理・プロジェクト切替を先に入れない。版管理は原本 revision / `index_build` / KB snapshot の 3 層 | 確定 |
| D-09 | KB / 影響分析の境界 | **内容面は KB、分析面は Impact、共通カーネルを共有**（ADR-016） | 二重パイプラインを作らない。Impact は revision / index / snapshot ID だけを持ち、原本 / chunk / evidence を複製しない | 確定 |

同時に確定した前提：

| 項目 | 結論 |
|---|---|
| A-07 コード自動修正 | **行わない**。差分提案まで。Phase 7 で書き込み権限は実装しない |
| 体制 | **Rust 2 名 + フロント 1 名 + 設計 0.5 名**。Phase 4 は Java 0.5 名、Phase 5 から QA 1 名を追加 |

## 6. 本設計書の対象外

- Cargo workspace と業務コードの生成（Phase 1 以降で段階的に実施）
- Prompt 第 20 節に列挙された 29 冊の設計書の全文。本書はそのうち 9 部分の**実装可能版**であり、Security Design / Monitoring Design / Deployment Design の詳細版は各 Phase の開始前に補完する

- 顧客実システムに対する性能保証。目標値は Phase 2 / 4 で実データにより校正する
