# 第七部分：UI 设计

## 1. 定位

**Modern Developer Workbench + Engineering Intelligence Workspace**，不是 ERP 后台。

三条视觉与交互主张：

1. **信息密度优先**。企业项目的价值在细节，一屏能看到 20 行比看到 8 行有用。用留白做分组，不用留白做装饰。
2. **分析过程可见**。加载不是转圈，而是「正在解析第 128/240 个文件」。用户要能判断「还要等多久」和「是不是卡住了」。
3. **证据随手可及**。任何结论旁边都能一键展开原文，而不是跳到另一个页面再找回来。

### 3.1 A-04 影响分析（主工作台）

```text
├──────────────────┬──────────────────────────────────┬─────────────────────────┤
│ ① 変更内容        │ ② 影響グラフ                      │ ③ 影響項目               │
│                  │                                  │                         │
│ ▾ src/           │      [Screen]                    │ L2 呼び出し元            │
│   ▾ UserEdit     │         ▲                        │ ┌─────────────────────┐ │
│     Action.java  │         │ HANDLES                │ │ UserBatchService    │ │
│       L128 ●     │   [Action] ──CALLS──▶ [Service]  │ │ 経由: CommonValid.. │ │
│       L131 ●     │         │                │       │ │ 信頼度 0.92  [詳細] │ │

│       jsp  L74 ● │         ▼                ▼       │ │ AddressValidator    │ │
│                  │      [Table]         [Validator] │ │ 直接  RESOLVED      │ │
│ + 変更を追加      │                                  │ └─────────────────────┘ │
│                  │  □ 直接のみ □ 未解析含む          │                         │
│ フィルタ:         │  ⚠ 1 件のハブを展開していません    │ [テスト計画を生成]       │
│ ☑ コード ☑ 設計   │                                  │                         │
├──────────────────┴──────────────────────────────────┴─────────────────────────┤
│ ④ エビデンス（選択項目）: 詳細設計書 画面項目定義 C12:F12  [原文を開く]          │
└───────────────────────────────────────────────────────────────────────────────┘
```

设计要点：

- 三栏可折叠，中间图与右侧列表**双向联动**（选节点 → 列表滚动；选列表 → 图高亮）。
- 顶部常驻「影响数 / 未解析数 / 风险」，这三个数字决定用户是否信任这份报告。
- 「未解析含む」是显式开关，默认**开**。隐藏不确定性是最危险的设计。
- 重新执行保留上一次结果做对比（`A-06` 提供 diff）。

## 4. 可视化方案

### 4.1 分工（硬边界）

| 库 | 用于 | 节点量级 | 布局 | 不做 |
|---|---|---|---|---|
| **Cytoscape.js** | Ontology、依赖图、影响图、追踪图 | 10 ~ 5,000 | dagre / cose-bilkent / 自定义分层 | 表单、流程编排 |
| **React Flow** | Workflow、Agent 流程、审批流 | 5 ~ 80 | 手动 + 自动对齐 | 大规模关系分析 |

混用的后果：Cytoscape 做流程编辑器很痛苦（自定义节点 UI 弱），React Flow 做 5000 节点图会卡死。

### 4.2 Cytoscape 交互规范

| 交互 | 行为 |
|---|---|
| 悬停节点 | 高亮 1 跳邻居，其余降透明度至 0.15 |
| 单击 | 选中 + 右侧详情面板更新（不发请求，用已加载数据） |
| 双击 | 展开下一层（增量请求，带 loading 骨架） |
| 右键 | 上下文菜单：以此为中心 / 隐藏 / 只看该路径 / 复制 ID |
| 框选 | 批量操作（加入测试范围 / 导出子图） |
| 滚轮 | 缩放；`Shift+滚轮` 横向平移 |
| 搜索 | 命中节点脉冲高亮 + 自动居中 |
| 布局切换 | dagre（层次）/ cose（聚类）/ 同心圆（影响层级） |

视觉编码：

| 维度 | 编码 |
|---|---|
| 实体类型 | 形状（圆=类/方法，方=画面，菱形=表，六边形=业务规则）+ 颜色 |
| 解析状态 | 线型（实线=RESOLVED，虚线=INFERRED，点线=PARTIAL，灰色虚线=UNRESOLVED，红双线=CONFLICT） |
| 影响方向 | 边颜色（上流=橙，下流=蓝，共享资源=紫） |
| 风险 | 节点描边粗细 |
| 截断 | 节点外圈虚线 + 「+N」角标 |

**不允许**只用颜色区分状态（色觉障碍）。形状与线型必须同时变化。

### 4.3 性能

- 超过 800 节点：切换到「聚合视图」（按 Package/Module 折叠），展开时按需加载。
- 超过 3000 节点：禁用动画，使用 Canvas 渲染器（非 SVG）。
- 布局计算放 Web Worker，避免阻塞主线程。
- 增量渲染：只更新变化的节点/边，不整图重绘。

## 5. 交互设计

### 5.1 全局

| 功能 | 规则 |
|---|---|
| 命令面板 | `⌘K`，可跳页面、搜实体、执行动作（受权限约束） |
| 作业中心 | 右上角常驻，显示运行中作业；点击展开抽屉；不阻塞其他操作 |
| 通知 | 只对「需要人决策」的事件推送（审批、失败、漂移告警）；进度不进通知 |
| 主题 | 亮/暗双主题，跟随系统；图表颜色两套都需验证对比度 |
| 密度 | 表格支持「標準 / 高密度」切换，存用户偏好 |
| 快捷键 | `G then I` 跳影响分析、`/` 聚焦搜索、`Esc` 关抽屉 |

### 5.2 状态设计（每页必须定义）

| 状态 | 要求 |
|---|---|
| 加载 | 骨架屏 + 阶段文字（「解析中 128/240」），不用全屏 spinner |
| 空 | 说明「为什么空」+ 下一步动作（例：「尚未导入设计书」+「导入」按钮） |
| 错误 | 错误码 + 人话 + 重试按钮 + trace_id（可复制给支持） |
| 部分失败 | 显示成功部分 + 失败清单，不整体报错 |
| 权限不足 | 说明缺哪个权限、找谁申请，不显示空白页 |
| 截断 | 明确提示「结果已截断（原因：深度/预算/枢纽）」，并提供缩小范围的入口 |

### 5.3 表单与编辑

- 长表单分步（测试用例编辑：基本信息 → 步骤 → 数据 → 证据 → 审阅）。
- 破坏性操作二次确认，且需要**输入资源名**（不是只点「确定」）。
- 自动保存草稿（每 5 秒或失焦），显示「保存済み 12:03」。
- 离开未保存页面时拦截。

### 5.4 无障碍

- WCAG 2.1 AA；焦点可见；所有交互可键盘完成。
- 图可视化提供「表格视图」替代（屏幕阅读器无法读图）。
- 对比度 ≥ 4.5:1（正文）、3:1（大字与图形边界）。

## 6. 日语界面设计原则

不是「翻译成日语」，是「按日本企业软件的习惯设计」。

### 6.1 文体

| 场景 | 文体 | 例 |
|---|---|---|
| ラベル・見出し | 体言止め（名词短语） | 「影響範囲」「未解析項目」 |
| 説明・ヘルプ | です・ます | 「この操作は取り消せません。」 |
| エラー | 簡潔な断定 + 対処 | 「設計書を読み込めませんでした。ファイル形式を確認してください。」 |
| 確認ダイアログ | 結論先出し | 「この影響分析を削除しますか？削除すると元に戻せません。」 |

避免：

- 過剰な敬語（「させていただきます」连发）。
- 直译腔（「あなたのプロジェクト」→「プロジェクト」）。
- 英语直搬（「サブミット」→「登録」）。
- 感叹号与 emoji（企业软件里显得不专业）。

### 6.2 用語統一（用語集，开发前定稿）

| 概念 | 日语 | 禁止说法 |
|---|---|---|
| Project | プロジェクト | 案件、 PJ（口语可用但 UI 不用） |
| Screen | 画面 | スクリーン、ページ |
| Design doc | 設計書 | ドキュメント（泛称时才用） |
| Impact | 影響範囲 | インパクト |
| Traceability | トレーサビリティ | 追跡可能性 |
| Coverage | カバレッジ | 網羅率、被覆率（混用禁止，选一个） |
| Unresolved | 未解析 | 不明、エラー |
| Evidence | エビデンス | 証拠（法律感太强） |
| Scenario | シナリオ | シーナリオ |
| Test case | テストケース | テスト項目（易混） |

术语表存 `docs/ui/glossary-ja.md`，CI 检查 UI 文案中不出现禁用词。

### 6.3 表記ルール

| 項目 | ルール | 例 |
|---|---|---|
| 日付 | `yyyy/MM/dd` | `2026/11/05` |
| 日時 | `yyyy/MM/dd HH:mm` | `2026/11/05 20:02` |
| 年度 | 4 月始まり、`2026年度` | 会計年度の集計に使用 |
| 数値 | 半角、3 桁区切り | `1,234` |
| 割合 | 整数 + `%`、小数第 1 位まで | `82.4%` |
| 金額 | `¥1,234,567`（半角） | — |
| 単位 | 半角スペース区切り | `12 件` `3.4 秒` |
| 括弧 | 全角 `（）` 日本語 / 半角 `()` 英語・コード | — |
| 句読点 | `、` `。` | 不用 `,` `.` |
| カタカナ | 全角、長音記号を省略しない | `コンピューター`（不是 `コンピュータ`），按 JIS 规则统一 |
| 英字 | 半角。固有名詞は原綴り | `Playwright` `Neo4j` |

### 6.4 レイアウトとタイポグラフィ

| 項目 | 値 | 理由 |
|---|---|---|
| 本文 | 14px / 行間 1.7 | 日本語は行間を広めに取らないと詰まって見える |
| 表内 | 13px / 行間 1.5 | 情報密度確保 |
| 補助 | 12px | 単位・注記 |
| 見出し | 16 / 20 / 24px | — |
| フォント | `Noto Sans JP`（本文）、`BIZ UDPGothic`（代替）、`JetBrains Mono`（コード） | 可商用、Web フォント配信可、等幅で日本語コメントも崩れない |
| 最大行長 | 全角 40 文字程度 | それ以上は読まれない |
| 禁則処理 | 行頭に `」、。ー` を置かない／行末に `「（` を置かない | 日本語組版の基本。PDF 帳票出力では必須 |
| 余白 | 4px グリッド、セクション間 24px | 詰めすぎず、間延びさせない |

### 6.5 情報密度

日本企业用户习惯「一覧で見る」。因此：

- 列表默认显示 50 行（不是 20），提供密度切换。
- 关键属性列常驻，不做「点击展开才看到」。
- 筛选器默认收起但保留已选条件标签（chips），一眼可见当前过滤。
- 不用大面积卡片式布局做列表（浪费纵向空间）。

### 6.6 国際化

| 項目 | 方針 |
|---|---|
| デフォルト | `ja` |
| 対応 | `ja` / `zh-CN` / `en` |
| 実装 | i18next + ICU MessageFormat |
| キー命名 | `domain.component.element`（`impact.list.empty`） |
| 禁止 | 文字列連結で文を組み立てる（語順が壊れる） |
| 複数形 | ICU `plural` を使う（日本語は 1 種だが英語は 2 種） |
| 検索正規化 | 全角/半角、ひらがな/カタカナ、旧字体を同一視（DB 側で正規化列を持つ） |
| ソート | 日本語ロケールの照合順序（`ja-x-icu`）を使用。コードポイント順にしない |
| 数値・日付 | `Intl.NumberFormat` / `Intl.DateTimeFormat` |
| タイムゾーン | 保存は UTC、表示は `Asia/Tokyo` |

### 6.7 エラーメッセージの型

```text
【何が起きたか】+【なぜか】+【どうすればいいか】

× エラーが発生しました。
○ 設計書の解析に失敗しました。ファイルがパスワード保護されている可能性があります。
  保護を解除してから再アップロードしてください。

× 権限がありません。
○ この操作には「テスト承認」権限が必要です。プロジェクト管理者に依頼してください。
```

错误码放第二行小字（`E-DOC-0042 / trace: 4bf9...`），方便支持人员定位，又不干扰普通用户。

## 7. 前端工程约束

| 约束 | 说明 |
|---|---|
| 路由即状态 | 筛选、排序、选中项写进 URL；刷新可恢复 |
| 不重复类型 | API 类型由 OpenAPI 生成，前端不手写 |
| 组件分层 | `ui/`（无业务） → `features/`（业务） → `pages/`（编排） |
| 图组件隔离 | Cytoscape 与 React Flow 各自封装，不共享状态 |
| 性能预算 | 首屏 JS < 300KB（gzip）；图页面单独 chunk |
| 错误边界 | 每个 feature 一个 ErrorBoundary，避免整页白屏 |
| 测试 | 关键交互用 Playwright 覆盖（平台自己的 E2E），组件用 Testing Library |
